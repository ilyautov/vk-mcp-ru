# Установка vk-mcp-ru агентом

Сборка не нужна: пакет лежит на PyPI, `uvx` ставит и запускает его одной
командой. Клонировать репозиторий не надо.

## 1. Проверить uv

```bash
uv --version
```

Команды нет: поставить по инструкции с https://docs.astral.sh/uv/ и повторить.

## 2. Записать сервер в настройки MCP

В `cline_mcp_settings.json` (или в конфиг своего клиента) добавить:

```json
{
  "mcpServers": {
    "vk-mcp": {
      "command": "uvx",
      "args": ["vk-mcp-ru"],
      "env": { "VK_TOKEN": "" }
    }
  }
}
```

## 3. Спросить ключи у человека

Ключи выдаёт сам сервис, получить их за пользователя нельзя.

dev.vk.com → приложение → сервисный ключ доступа, либо токен сообщества с правами market, messages, ads, stats. Запрашивайте только те права, которые реально нужны.

| переменная | секрет | что это |
|---|---|---|
| `VK_TOKEN` | да | Сервисный ключ приложения VK или токен сообщества с нужными правами. |

Ключи можно не класть в конфиг: у сервера есть кабинеты, команда
`vk_add_cabinet` кладёт их в `~/.ru-mcp/cabinets.json` с правами 600. Тогда
в `env` остаются пустые строки, и секрет не попадает в файл настроек клиента.

## 4. Проверить

```bash
uvx vk-mcp-ru doctor
```

Печатает число загруженных методов и то, найдены ли ключи. Секреты не
показывает. Установка удалась, если в выводе есть строка с числом методов.

После перезапуска клиента у агента появляются инструменты `vk_search_methods`,
`vk_describe_method`, `vk_call_method` (чтение),
`vk_write_method`, `vk_delete_method`, `vk_map` и кабинеты. Начинать
стоит с `vk_map`: он показывает разделы каталога и не требует ключей.

## Что может пойти не так

- `uvx` не находит пакет: проверить сеть и доступность pypi.org.
- Инструменты не появились: клиент читает конфиг при старте, его надо
  перезапустить.
- Вызов отвечает 401 или 403: ключей нет либо они не той учётной записи,
  `doctor` покажет, откуда сервер их берёт.
- Запись и необратимые методы отвечают отказом до подтверждения: это гейт
  безопасности, а не ошибка.
